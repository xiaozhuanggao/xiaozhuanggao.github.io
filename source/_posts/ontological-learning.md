# 本体论的学习：我们到底在学"什么"

FDE 这三个字母我拖了很久才动笔，不是没话说，是怕说浅了。它本该是一门正经学问的缩写，落到我这儿，倒更像一句没说完的提醒：**我们学一样东西的时候，到底在学它的什么。**

## 记名字不等于认得

小时候背"这是猫，那是狗"，以为认识了世界。后来才发觉，能叫出名字离"认得"还差着一层——你得分得清它**是**什么，而不只是它**叫**什么。

哲学里有个词叫本体论，问的正是这个：一个事物，它"是"什么。不是它的颜色、价格、用途，是更底下的那句——它凭什么被算作它自己，而不是别的。

这套问法看着玄，其实天天在用。你学一个新框架，若只记住了它的 API 名字和几个例子，换个项目就懵；可一旦你弄明白它"是"为了解决哪类问题才存在的，哪怕 API 忘了也能推出来。前者记的是标签，后者认的是本体。

## 知识库里的那个坑

做知识类系统的人迟早会撞上一个墙：你收进来的东西越多，越容易变成一座贴满标签的仓库，而不是一座能让人想通事的房子。

根子常在分类的方式。按名字分、按来源分、按格式分，都省事，也都危险——因为事物真正的亲缘关系，常常藏在"是做什么用的"底下，不在"叫什么"表面。一个用来"快速验证想法"的原型，和一个用来"长期承载业务"的服务，名字可能天差地别，本体上却是近亲。

认错本体，后面全歪。你把该并列的拆开了，把该拆开的并在一起，检索越准，误导越深。

## 所以"学"这件事得分两层

一层是往脑子里塞东西：概念、术语、案例。这层不难，重复就够。

另一层慢得多，也贵得多：让新东西在你已有的认知里**找到它的位置**——它和什么是一伙的，和什么是貌合神离，它在哪类问题上管用、在哪类问题上会骗你。

第一层帮你显得懂，第二层才让你真的懂。多数人停在第一层就以为到了头，于是收藏夹越来越长，判断力没怎么长。

我后来养成一个笨习惯：每碰到一个新东西，先不问"它怎么用"，而是问"它**是**个什么"。这问题没有标准答案，但凡认真答过一遍，后面再学相关的就轻。

> 名字是别人给的，本体是自己长的。只记名字的人，永远在借别人的眼睛看世界。
