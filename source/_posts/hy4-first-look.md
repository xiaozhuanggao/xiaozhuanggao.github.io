# 腾讯 Hy4 首发速评：770B 跑分该怎么读

> 发布当天最值得读的，不是那张跑分表，而是官方自己写在最后一节的「局限性」。

## 先把边界说清楚

这不是一篇实测。今天（2026-11-04）腾讯混元 Hy4 正式版刚发布，我还没在自己的业务任务上跑过它，所以本文不会给出「我实测多少分」「比某某快多少」这类结论。

我做的是两件事：把发布日能查到的公开数据按来源分层核一遍，标出哪些数字不能横向比；再给一套我接下来会用的复测题单。发布当天的稿子很多，但绝大多数是同一份材料的转述，缺的恰恰是这一步。

这和我写《主流大模型横评》时的立场一致：benchmark 看方向，真实任务才做决策。

> 立场说明：文中数据全部来自公开发布材料与第三方榜单，无厂商合作、无送测、无赠额。凡标「自测」处，均为原发布方口径，未经独立复现。

## 一、先确认我们在聊哪个版本

Hy4 有两个版本，中间隔了两个月。今天很多稿子把两代参数混在一行写，这是第一个坑。

| 项 | Hy4 preview（2026-08-28） | Hy4 正式版（2026-11-04） |
|---|---|---|
| 总参数 / 激活参数 | 770B / 49B，MoE | **官方研究页未披露** |
| 上下文窗口 | > 1M tokens（1,048,576） | 未单独披露 |
| 视觉理解 | 无（text → text） | **首次引入**，细粒度图像、复杂图表、带图推理 |
| Computer Use | 无 | **首次支持**，命令行 + 图形界面，针对 Blender / CAD 专项训练 |
| 权重 | 已开源 | **计划开源，未给日期**；系统卡片待发 |
| API 调用名 | `hy4-preview` | `hy4` |
| 价格（每百万 tokens） | 输入 6 元 / 输出 18 元 / 缓存命中 0.3 元 | 维持不变 |

数据来源：腾讯官方英文发布稿（preview 规格）、腾讯混元官方研究页《Hy4 正式发布》、腾讯云 TokenHub 价目转述。第三方榜单把 preview 的许可证记为 Apache-2.0，正式版以官方仓库为准。

**那个坑**：官方研究页通篇只说「显著扩展了预训练和后训练规模」，没给参数量；同花顺的报道也明确写了「腾讯没有披露参数量」。770B / 49B / 1M 是 8 月 preview 的官方数字。「扩展」不等于「沿用」，写技术文档时别替厂商把这一格补上。

## 二、跑分要分三层，别拼成一张表

| 层 | 发布日可见的数据例子 | 能用来做什么 |
|---|---|---|
| A. 官方自测 | WorkBuddy 办公场景平均 83.18 分、任务通过率 96.15%，12 个场景中 9 个国内第一；213 位专家 / 579 个真实金融任务众测 3.04/4（DeepSeek-V4.1-Flash-1017 2.97、Kimi K3.1 Pro 2.68、GLM-5.3 2.68）；GameDev +19.1%、GameLogic +9.8% | 看**自家版本间的进步方向**，不做跨厂商排名 |
| B. 官方引用的公开成绩 | 附录对比表里标注「公开成绩」的 Kimi / Claude 分数；Agent Arena 第 14 名（preview 第 25 名），每任务成本中位数 0.55 美元 | 看相对位置，但要对齐版本串 |
| C. 第三方独立复现 | **发布当天基本空白**：Artificial Analysis 未收录，开源社区无复现数据 | 目前无法用于选型决策 |

### 三个具体的口径问题

**1. 自测成绩与公开成绩混在同一张对比图里。** 有媒体逐项核对后发现：ProgramBench 上，腾讯自测的 Kimi 成绩低于 Hy4，但附录列出的 Kimi 公开成绩反而更高，两组数字的先后关系不一致；同一张图里，Kimi / Claude 用的是公开成绩，GPT / DeepSeek 标的是腾讯自测。同一坐标轴上混了两种测量方式，「赢了多少分」就不能按字面读。APEX-Agents 里 Hy4 在腾讯自测中超过一众模型，而 Terminal-Bench 4.0 上仍落后于 GPT、Claude 和 Kimi——这两句同时成立，取决于你看哪张图。

**2. 同一天出现两组幻觉率。** 腾讯新闻稿写「从 preview 的 12.95% 降至 7.2%」，官方研究页写「从 15.76% 降至 5.45%」，另有媒体把后者表述为「搜索幻觉率」。猜测导致的错误率倒是两处完全一致（23.1% → 5.6%）。我不判断谁对，更可能是整体与搜索场景的测试集不同；但既然测试集、判定标准、样本量都没公开，这个数字只能当方向性改善，不能拿去和别家模型的幻觉率比大小。

**3. 对比组型号名对不齐。** 发布日材料里同时出现 GPT-6.1 Sol / GPT-5.6 Sol、Claude Opus 5.5 / Opus 5、Kimi K3.1 Pro / K3、DeepSeek-V4.1-Flash-1017 / V4 Pro 0813。这是 preview 期与正式版期两组不同的对比对象。跨稿拼表会得出不存在的结论。

所以：**分数可以信方向，别信绝对值**。方向是——正式版明显强于 preview，办公、Agent、金融是重投入区；「跻身最强开源模型之列」是厂商自我定位，不是可验证的排名。

## 三、官方自己承认的局限，比跑分更值钱

官方研究页最后一节原文写着：尽管 Hy4 已经是目前最强的开源模型之一，**其与顶尖闭源模型仍然存在较大差距**，尤其在内部构建的前沿数学、长程开发、模型迭代、视觉问答等高难度测试集上。

这段值得单独拎出来，有三个理由：

- 厂商在发布稿里写明「差距较大」并点名四个方向，比一句「全面领先」信息量大得多；
- 它给了一个反向校准：凡是宣称 Hy4 全面超越闭源旗舰的转述，都与一手材料矛盾；
- 对做技术选型的人，这四个方向正好是自测清单的优先级。

另一个被通稿略过的是**安全章节**：官方说训练阶段只纳入 PoC 生成、漏洞修复等防守性网络安全数据，剔除了漏洞利用、逆向、渗透类攻击性内容，并组织玄武、科恩实验室做过审计；生物方面 Hy-BioExperimentBench 得 30.4/100，未达高风险阈值。770B 加上 Computer Use 这个组合，能力边界和安全边界本来就该一起看。

还有**定价的信号**：性能显著提升但 API 价格不变，腾讯云五折到 12 月 31 日，WorkBuddy 11 月 4 日至 15 日每日赠免费额度；同时预告 Hy4 flash 主打性价比与推理速度。翻译一下——正式版负责把能力口碑立住，性价比这一仗留给 flash。现在不是算「划不划算」的时点。

## 四、我接下来会怎么测

沿用横评那套「同一道题、多模型、可复现」的方法，题单针对这次的四个卖点重新设计。这部分是全文唯一属于我自己的东西，也给需要的人直接拿去用。

| # | 任务 | 针对什么 | 判定口径 |
|---|---|---|---|
| 1 | 约 90 万 token 的混杂文档（代码库 dump + 财报 PDF），要求定位 5 处分散事实并给出处 | 1M 上下文是**可用**还是**可宣称** | 5 处全中且出处可核验；记录耗时与输入 token |
| 2 | 给一张带复杂图表的截图，读出数据并做一次计算 | 首次引入的视觉 | 数值读数正确率；是否编造图中不存在的系列 |
| 3 | 200 行代码藏 3 个 bug，要求定位并给补丁 | 主打的长程开发与调试 | 命中数、误报数、补丁能否直接跑通 |
| 4 | 十轮连续指令，每轮追加一条格式约束（引用样式、编号、逐条修改说明） | 指令遵循 / 人机双写 | 最后一轮是否仍满足前九轮全部约束（累积遵循率） |
| 5 | 需要命令行 + GUI 跨应用的任务，例如从表格生成图、插入文档、导出 PDF | Computer Use | 是否完成、中途失败能否自恢复、有无越权操作 |
| 6 | 一组带时效性的问题要求给出来源，故意混入查不到的条目 | 幻觉率下降是否在我的场景成立 | 「不知道」的命中率、伪造引用数 |

记录模板固定成一行一个模型：版本串 / 温度与推理档 / 输入 token / 输出 token / 耗时 / 成本 / 通过与否 / 失败点 / 复现备注。

两个纪律：**同一个版本串、同一组参数跑三轮取中位数**；**必须记版本串**。发布期模型迭代快，不记版本的结果两周后就没有可比性了。等权重和系统卡片放出，第 3、5 题还可以搬到私有部署上再跑一遍，顺便把推理成本一起量出来。

## 五、现在该不该切

| 你的情况 | 建议 |
|---|---|
| 主力是办公文档、数据分析、长文整理 | 值得现在试，用免费额度跑第 1、4 题，成本为零 |
| 主力是写代码、Agent 长程任务 | 小流量灰度，重点跑第 3、5 题；官方点名「长程开发」仍有差距 |
| 需要私有化或可控部署 | 等权重与系统卡片，日期未定 |
| 成本敏感 | 等 Hy4 flash |
| 习惯看榜单做决策 | 等第三方复现，现在只有厂商口径 |

## 一句话结论

Hy4 正式版最实质的变化不是参数，是「从会回答到会执行」——视觉、Computer Use、长程 Agent，配套的是办公与金融场景的重投入；而发布日所有分数都还是厂商口径，第三方复现为空白。今天可以开始测，不适合下结论。
