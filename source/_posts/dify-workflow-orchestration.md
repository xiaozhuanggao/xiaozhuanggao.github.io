# Dify 编排企业级 Workflow

> 当 AI 能力要真正落地到业务，靠的不是"聊天框"，而是一条条可控、可调试、可复用的 Workflow。Dify 是编排这些工作流的利器。

## 为什么用 Workflow 而不是纯 Agent

一开始我们也试过"让 Agent 自由发挥"，结果很惨：Agent 会乱调用工具、输出不稳定、难以调试。

**Workflow 的价值在于"可控"**：把 AI 能力拆成一条明确的执行链，每一步做什么、走哪个分支都是确定的。对企业场景，可控比"聪明"重要得多。

## 核心节点类型

Dify 的 Workflow 由几种节点拼成：

| 节点 | 作用 |
|------|------|
| LLM | 调大模型生成 |
| 知识检索 | 从知识库召回 |
| 工具 | 调用外部 API / 自定义代码 |
| 条件分支 | 根据结果走不同路径 |
| 变量聚合 | 汇总多个分支的结果 |

## 一个真实场景：气量智能问数

以我做的"自然语言查数据"为例，Workflow 大概是这样的：

```text
用户提问（"上个月各营业厅的用气量是多少"）
        ↓
LLM：意图识别 + 实体抽取（时间、指标、维度）
        ↓
工具：根据表结构生成 SQL
        ↓
工具：执行 SQL（带权限校验）
        ↓
LLM：把查询结果组织成自然语言回答
```

关键在**中间的工具节点**——SQL 生成和执行都被封装成可复用的工具，LLM 只负责"理解"和"表达"，不碰数据。

## 调试技巧

Dify 的 Workflow 调试是它的强项：

- **单节点调试**：能单独看某个节点的输入输出，不用从头跑
- **回溯**：每一步的中间结果都能展开看，方便定位"哪一步出错了"

用好这两个能力，排查 Workflow 问题比纯代码调试还直观。

## 生产落地要点

- **错误处理**：工具调用要 try-catch，异常时返回友好信息而不是整个流程崩溃
- **权限控制**：工具节点要校验当前用户有没有权限执行这个操作
- **日志**：关键节点记录输入输出，便于线上追溯

## 小结

Dify 把"AI 能力编排"这件事从写代码降维到可视化拖拽，让业务团队也能参与。但对工程师来说，真正的价值在于**用 Workflow 把 AI 能力产品化、工程化**——可控、可调试、可复用，这才是从 Demo 走向生产的关键。
